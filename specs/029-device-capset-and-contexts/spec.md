### Design rules — binding on this feature

Constitution Principle III and [`CLAUDE.md`](../../CLAUDE.md). Restated here because it is checked at review, not assumed:

- **Every unit of behaviour is a class that owns state.** No static member functions. No stateless class used as a namespace. No free function outside the two ABI boundaries (`DxgkDdi*` entry points in `src/core/ddi/`, and `extern "C"` entry points), each one line with no logic.
- If functions thread the same handle, buffer, bounds or platform through their parameters, **that parameter is a member**. Make it a class and inject its dependencies at construction.
- Name the classes this feature adds before writing them, and say which kind each is: an **object class** (one instance per real thing) or a **system class** (a long-lived service owning a collection).
- Dependencies injected at construction. No global, no singleton, no file-scope state.
- Data members private, trailing underscore. Classes `PascalCase`, methods and locals `snake_case`. No `Manager`, `Helper`, `Utils`, `Handler`, `Impl`, `process()`, `handle()`.
- One class per header, named for it. A header declares; it does not define. One responsibility per class, statable without an "and".
- Errors are `av::Status` values. No exceptions, no RTTI, no C++ standard library, no `new`/`delete` (placement new only in `ObjectStorage`). Cleanup is RAII via `ScopeExit`, never repeated per branch.
- Fallible construction is two-phase: trivial constructor, `initialize(...)` returning `Status`.
- Every public method declares its IRQL ceiling via `platform_.require_irql_at_most(...)`.

## User Scenarios & Testing *(mandatory)*

<!-- Written by /speckit-specify or by hand. The autogen block above is regenerated by tools/gen_specs.py; everything below is preserved. -->

A guest driver reads the device's single capset, creates a context naming the
rvk capset id, and binds it with a context setup to a ring and a fence page it
created as blobs (028). The device refuses anything the capset does not allow,
keeps the bound blobs alive while the context lives, and forgets everything on
CTX_DESTROY or reset. The ring and fence page are not yet read (030, 031).

### Acceptance Scenarios

1. **Given** a realized device, **When** the guest reads its features and
   config, **Then** `VIRTIO_GPU_F_CONTEXT_INIT` is offered, `num_capsets` is 1,
   and nothing else differs from stock virtio-gpu.
2. **Given** capset index 0, **When** the guest sends GET_CAPSET_INFO, **Then**
   the answer is id 0x72, max version 1, max size 128; any other index is
   `ERR_INVALID_PARAMETER`.
3. **Given** GET_CAPSET for id 0x72 version 1, **Then** the 128 bytes decode as
   a valid `CapsetInfo`: protocol 1.0, Vulkan offered, 64 contexts, ring orders
   12..24, `host_visible_memory` exactly when a hostmem region exists, and the
   bound GPU's vendor, device, type, UUID, heap sizes and name.
4. **Given** CTX_CREATE with `context_init` naming capset 0x72, **Then** the
   context exists; id 0, a live id, another capset id, a debug name longer than
   64 bytes, or a short request are refused with the documented errors.
5. **Given** a created context and two blobs, **When** the guest submits a
   32-byte context setup with SUBMIT_3D, **Then** the context records the
   negotiated version `1.min(minor)`, the sub-API, the ring and fence resources
   and the ring order; the blobs cannot be unreferenced until CTX_DESTROY.
6. **Given** a setup with another major, an unoffered sub-API, a ring order
   outside the capset, a missing resource, a ring blob smaller than
   `32 + 2^order` bytes, a fence blob smaller than 32 bytes, malformed bytes,
   a size field that disagrees, or a context already set up, **Then** the setup
   is refused and the context stays unbound.
7. **Given** contexts with bindings, **When** the device resets, **Then** every
   context is destroyed before any blob is released, and both can be created
   again.

## Requirements *(mandatory)*

- **FR-001**: The core decides what is offered: `rvk_device_capsets` answers the
  capset count and the glue offers `VIRTIO_GPU_F_CONTEXT_INIT` from it.
- **FR-002**: Every request field is bounded before any state changes; every
  refusal is one response with the documented error.
- **FR-003**: A context's bound blobs outlive its binding; UNREF of a bound blob
  is `ERR_INVALID_PARAMETER` and releases nothing.
- **FR-004**: The capset is described once, at realize, from the host GPU the
  device is bound to.
- **FR-005**: `docs/protocol.md` documents the context commands and answers.

## Success Criteria

- **SC-001**: The qtest suite reads the capset from the real device, creates,
  sets up and destroys contexts, and checks every refusal and reset.
- **SC-002**: 100% branch coverage of the new core; `fuzz_context_request` clean.

## Out of Scope

- Reading the ring or fence page, doorbells, fence rings (030, 031).
- Executing any API (032); GL and CL sub-APIs (M7).
- CTX_ATTACH_RESOURCE / CTX_DETACH_RESOURCE: left to the base class.

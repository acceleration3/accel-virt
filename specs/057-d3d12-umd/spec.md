# Feature Specification: Direct3D 12: the user-mode driver

**Feature Branch**: `057-d3d12-umd`

**Created**: 2026-09-11

**Status**: Draft

<!-- AUTOGEN:BEGIN -->

**Feature ID**: 057 · **Status**: `implement` · **Depends on**: 056

The D3D12 UMD DDI over Vulkan remoting - command queues and lists, descriptor
heaps, pipeline states with DXIL translated to SPIR-V, residency through
MakeResident and Evict, and fences - so applications using the system
d3d12.dll run on rvkgpu with no DLL replaced, at the feature level the host
GPU supports.

### Status meaning

Build it, test it to the constitution's standard, and report the capabilities it enables.

### Design rules — binding on this feature

Constitution Principle III and [`CLAUDE.md`](../../CLAUDE.md). Restated here because it is checked at review, not assumed:

- **Every unit of behaviour is a class that owns state.** No static member functions. No stateless class used as a namespace. No free function outside the two ABI boundaries (`DxgkDdi*` entry points in `src/core/ddi/`, and `extern "C"` entry points), each one line with no logic.
- If functions thread the same handle, buffer, bounds or platform through their parameters, **that parameter is a member**. Make it a class and inject its dependencies at construction.
- Name the classes this feature adds before writing them, and say which kind each is: an **object class** (one instance per real thing) or a **system class** (a long-lived service owning a collection).
- Dependencies injected at construction. No global, no singleton, no file-scope state.
- Data members private, trailing underscore. Classes `PascalCase`, methods and locals `snake_case`. No `Manager`, `Helper`, `Utils`, `Handler`, `Impl`, `process()`, `handle()`.
- One class per header, named for it. A header declares; it does not define. One responsibility per class, statable without an "and".
- Errors are `av::Status` values. No exceptions, no RTTI, no C++ standard library, no `new`/`delete` (placement new only in `ObjectStorage`). Cleanup is RAII via `ScopeExit`, never repeated per branch.
- Fallible construction is two-phase: trivial constructor, `initialize(...)` returning `Status`.
- Every public method declares its IRQL ceiling via `platform_.require_irql_at_most(...)`.

## User Scenarios & Testing *(mandatory)*

<!-- Written by /speckit-specify or by hand. The autogen block above is regenerated by tools/gen_specs.py; everything below is preserved. -->

Users: applications that load the system `d3d12.dll` - games, engines,
DirectML and any D3D12 consumer that cannot have vkd3d-proton placed beside it
- and the parts of Windows built on D3D12. They need D3D12Core to find a real
D3D12 driver on rvkgpu, at the feature level the host GPU honestly supports.

### User Story 1 - D3D12 applications render through the system runtime (Priority: P1)

**Independent Test**: in the guest, the D3D12 samples (hello triangle,
bundles, constant buffers, descriptor heaps with unbounded ranges, compute,
multithreading, heterogeneous resource states, predicted rendering) run on
rvkgpu with no DLL beside them; frames are compared against references within
tolerance. On Linux, the translation core replays the recorded DDI sequences
against the loopback rig and a mock executor.

**Acceptance Scenarios**:

1. **Given** a D3D12 device on rvkgpu from feature 055, **When** the
   application creates command queues, allocators, lists, heaps, placed and
   committed resources, descriptor heaps and root signatures, **Then** each
   becomes host Vulkan state over the transport.
2. **Given** DXIL pipeline states the runtime has validated, **When** they are
   created, **Then** they are translated to SPIR-V and run with results
   identical to the reference within tolerance, or creation fails with a
   logged reason.
3. **Given** a command list executed on a queue, **Then** its work completes,
   the queue's fence advances, and `ID3D12Fence` events fire at the values
   reached.

### User Story 2 - Residency and memory budgets behave (Priority: P1)

**Independent Test**: a probe fills the adapter past its budget, calls
`MakeResident` and `Evict`, and watches `QueryVideoMemoryInfo`; the driver
never loses content that is resident, and eviction frees budget as reported.

**Acceptance Scenarios**:

1. **Given** allocations beyond the budget, **When** the application makes a
   subset resident, **Then** the UMD's residency calls map to the KMD's
   paging (features 017, 041) and to host memory state, and a draw touching an
   evicted resource fails as D3D12 specifies.
2. **Given** the budget changes, **Then** budget notifications reach the
   application.

### User Story 3 - The feature level and options are truthful (Priority: P1)

**Independent Test**: every answer to `CheckFeatureSupport` - feature level,
shader model, tier values, options structures - is backed by a named passing
test and gated on capset bits; a table test lowers each answer when the host
capability it depends on is withdrawn.

**Acceptance Scenarios**:

1. **Given** a host GPU with ray tracing and mesh shaders, **When** the level
   and tiers are complete and tested, **Then** they are reported; otherwise
   they are reported unsupported.
2. **Given** D3D12Core's device creation at a minimum feature level the UMD
   does not reach, **Then** creation fails with the status D3D12Core expects.

### Edge Cases

- Device removal while command lists are open: `GetDeviceRemovedReason`
  names the cause; the application's recreated device works after TDR.
- Several queues submitting from several threads; queue timeouts do not trip
  TDR while the host is progressing (`QueryEngineStatus`, feature 040).
- Shared heaps and resources with another process or a D3D11 device (feature
  053, `ID3D11On12`).
- WoW64 32-bit D3D12 applications.
- A shader model or tier the host cannot run: reported unsupported, never
  emulated incorrectly.
- Descriptor heaps larger than host limits: creation fails, no truncation.
- Pipeline library and cached PSO blobs from a different driver version:
  refused as mismatched, never decoded as trusted.

## Requirements *(mandatory)*

- **FR-001**: `rvkumd.dll` implements the D3D12 UMD DDI (`d3d12umddi.h`) that
  D3D12Core calls, the minimum set derived by reverse engineering
  `d3d12core.dll` (`docs/kb/12-re-cookbook.md`).
- **FR-002**: Queues, command lists, heaps, descriptor heaps, pipeline states,
  queries and fences map to host Vulkan over the transport; queue completion
  uses rvk fences and, with feature 049, native fences.
- **FR-003**: DXIL is translated to SPIR-V with the same observable
  requirement as feature 056; the translator is a plan decision.
- **FR-004**: Residency goes through the D3DKMT residency calls the KMD
  already implements; budgets come from the KMD's segments.
- **FR-005**: Feature level, shader model, tiers and options are reported only
  when implemented, tested and supported by the host capset (constitution VI).
- **FR-006**: Cached pipeline blobs carry a driver and host GPU identity and
  are validated as hostile input before use.
- **FR-007**: The translation core is portable C++ tested on Linux to the
  constitution's standard.

## Success Criteria *(mandatory)*

- **SC-001**: The D3D12 sample suite matches references through the system
  runtime.
- **SC-002**: The residency probe never observes lost resident content.
- **SC-003**: The HLK D3D12 graphics tests selected in feature 059 pass at the
  recorded rate.
- **SC-004**: A D3D12 application runs with the same results through the
  system runtime and through vkd3d-proton on the same host GPU.

## Assumptions

- Feature 056 exists: shared UMD infrastructure, resources and presentation.
- The host GPU exposes the Vulkan features D3D12 feature level 12_0 needs;
  lower hosts get a lower level or no D3D12.

## Out of Scope

- DirectML-specific and video (D3D12 Video) DDIs.
- DirectStorage GPU decompression.
- Multi-plane overlay and composition swapchains beyond what DXGI requires.

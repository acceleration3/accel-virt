# Feature Specification: OpenGL: compatibility profile and presentation

**Feature Branch**: `051-opengl-compatibility-and-present`

**Created**: 2026-09-11

**Status**: Draft

<!-- AUTOGEN:BEGIN -->

**Feature ID**: 051 · **Status**: `implement` · **Depends on**: 050, 046

The compatibility profile Windows OpenGL applications still use - fixed
function, immediate mode, legacy state - and SwapBuffers presented through
rvkgpu like Vulkan's swapchain, with swap intervals paced by the vertical
blank and no read-back through GDI.

### Status meaning

Build it, test it to the constitution's standard, and report the capabilities it enables.

### Design rules — binding on this feature

Constitution Principle III and [`CLAUDE.md`](../../CLAUDE.md). Restated here because it is checked at review, not assumed:

- **Every unit of behaviour is a class that owns state.** No static member functions. No stateless class used as a namespace. No free function outside the two ABI boundaries (`DxgkDdi*` entry points in `src/core/ddi/`, and `extern "C"` entry points), each one line with no logic.
- If functions thread the same handle, buffer, bounds or platform through their parameters, **that parameter is a member**. Make it a class and inject its dependencies at construction.
- Name the classes this feature adds before writing them, and say which kind each is: an **object class** (one instance per real thing) or a **system class** (a long-lived service owning a collection).
- Dependencies injected at construction. No global, no singleton, no file-scope state.
- Data members private, trailing underscore. Classes `PascalCase`, methods and locals `snake_case`. No `Manager`, `Helper`, `Utils`, `Handler`, `Impl`, `process()`, `handle()`.
- One class per header, named for it. A header declares; it does not define. One responsibility per class, statable without an "and".
- Errors are `av::Status` values. No exceptions, no RTTI, no C++ standard library, no `new`/`delete` (placement new only in `ObjectStorage`). Cleanup is RAII via `ScopeExit`, never repeated per branch.
- Fallible construction is two-phase: trivial constructor, `initialize(...)` returning `Status`.
- Every public method declares its IRQL ceiling via `platform_.require_irql_at_most(...)`.

## User Scenarios & Testing *(mandatory)*

<!-- Written by /speckit-specify or by hand. The autogen block above is regenerated by tools/gen_specs.py; everything below is preserved. -->

Users: people running Windows OpenGL applications that still use the
compatibility profile - fixed-function pipeline, immediate mode, display lists,
legacy state - which is most OpenGL software written for Windows before core
profiles; and everyone whose OpenGL frames must reach the desktop smoothly,
composed by DWM, at the display's refresh rate.

Starting point: render-server offers core 4.6 only. SwapBuffers sends
`kGlSwapBuffers`; the host reads the back buffer with `glReadPixels` into a
pinned present area and the guest blits it to the window DC through GDI, paced
by `RVK_GL_PRESENT_HZ`. The zero-copy shared-image path is not wired.

### User Story 1 - Legacy OpenGL applications run (Priority: P1)

**Independent Test**: loopback tests replay compatibility-profile command
sequences (immediate mode, `glBegin`/`glEnd`, matrix stacks, fixed-function
lighting and texturing, display lists, `glPushAttrib`, client arrays, selection
and feedback) and compare the host's decoded state and rendered pixels against
references.

**Acceptance Scenarios**:

1. **Given** an application that creates a context with `wglCreateContext` (no
   attributes), **When** it renders with fixed-function state, **Then** it
   receives the highest compatibility-profile version the host provides and the
   frame matches the reference image.
2. **Given** `WGL_CONTEXT_COMPATIBILITY_PROFILE_BIT_ARB`, **When** 3.2 or later
   is requested, **Then** a compatibility context is created or creation fails
   with `ERROR_INVALID_PROFILE_ARB` when the host has none.
3. **Given** display lists and `glCallLists` with thousands of lists, **When**
   they are compiled and called each frame, **Then** list contents live on the
   host and a call is one command, not a replay from the guest.
4. **Given** a host EGL that offers no compatibility profile, **Then** the ICD
   does not report one; the gap is logged once with the host's answer.

### User Story 2 - SwapBuffers presents through rvkgpu (Priority: P1)

**Independent Test**: in the guest, the application suite's GL frames are
captured at the host display and compared against references, and presents per
second are measured against the display's refresh rate with vsync on and off.

**Acceptance Scenarios**:

1. **Given** a double-buffered window, **When** `SwapBuffers` is called,
   **Then** the frame reaches the window through the same presentation path as
   Vulkan's swapchain (feature 046): a guest allocation the host renders into,
   presented with D3DKMT and composed by DWM, with no `glReadPixels` into guest
   memory and no GDI blit.
2. **Given** `wglSwapIntervalEXT(1)`, **When** frames are presented, **Then**
   presents are paced by the adapter's vertical blank; with 0, **Then** they
   are not, and tearing is DWM's choice, not the ICD's.
3. **Given** a window resized, minimized or covered, **When** the application
   keeps swapping, **Then** buffers are reallocated at the new size and
   occluded presents are skipped without blocking the render thread.
4. **Given** several GL windows in one process, **Then** each presents
   independently.

### Edge Cases

- A 32-bit WoW64 application: same presentation path, allocations mapped below
  4 GiB.
- `SwapBuffers` on a DC whose pixel format was set by another context, or
  after the window is destroyed: fails without touching another window.
- A single-buffered pixel format: `glFlush` presents, as on Windows.
- TDR during a present: the present fails, the context reports loss, DWM keeps
  the last frame.
- Mixed legacy and modern calls in one compatibility context (for example
  immediate mode into a framebuffer object): rendered as the host does.
- A host driver whose compatibility profile differs from another host's in
  edge behaviour: the reference images record the host they came from.
- An application reads the front buffer with `glReadBuffer(GL_FRONT)`: the
  last presented image is returned.

## Requirements *(mandatory)*

- **FR-001**: Compatibility-profile commands are forwarded to a host
  compatibility context; the guest keeps no parallel fixed-function emulation.
- **FR-002**: The compatibility profile and each legacy extension are reported
  only when implemented, tested and provided by the host (constitution VI).
- **FR-003**: Presentation shares what feature 046 built for Vulkan: the same
  `WindowSurface` and the same vertical-blank pacing, which moves to
  `src/icd/common/` so both ICDs hold one `FramePacer`.

  *As written this said "D3DKMT present". There is no such present: 046 does
  not have one either, because `DXGDEVICE::AllowLegacyPresent` refuses a legacy
  present from a device that does not own the VidPn source and the redirected
  present needs a user-mode driver's redirection surface (research.md §4,
  `docs/kb/07-usermode.md`). It arrives with feature 055, for both APIs at
  once.*
- **FR-004**: Buffer sizes, formats and present regions from the application
  are validated before any allocation or host command is made from them.
- **FR-005**: There is one present path, not two: no flag chooses between the
  old read-back and a new one (constitution VIII).

  *The GDI blit itself cannot be removed here - see FR-003 - and neither can
  the read-back, because no host driver imports guest memory into OpenGL
  (research.md §4). What 051 removes is every reason to read back a frame
  nobody will see.*

## Success Criteria *(mandatory)*

- **SC-001**: The application suite's compatibility-profile programs render
  frames matching references in the guest.
- **SC-002**: With vsync on, GL presents track the display refresh within the
  tolerance feature 046 sets for Vulkan; with it off, throughput is at least the
  read-back path's.
- **SC-003**: A swap on a window that cannot be seen reads nothing back at all,
  measured by the device's blob accounting.

  *As written this said no frame is ever read back. That is feature 055's to
  meet: OpenGL has no way to render into guest memory on either host driver
  (research.md §4), so the frame a window can see still crosses through the
  blob region.*

## Assumptions

- Feature 046's presenter and feature 050's ICD exist.
- Linux host GPU drivers expose a compatibility profile through EGL on
  desktop GL; where one does not (for example a GLES-only host), the profile is
  simply not reported.

## Out of Scope

- Stereo pixel formats, overlay and underlay planes, `wglUseFontOutlines`
  beyond what Microsoft's `opengl32.dll` implements over the ICD.
- Zero-copy composition on the host GPU without a guest allocation: feature
  058.

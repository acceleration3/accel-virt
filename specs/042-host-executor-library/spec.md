# Feature Specification: Host executor: this project's backends behind rvk_executor.h

**Feature Branch**: `042-host-executor-library`

**Created**: 2026-09-11

**Status**: Draft

<!-- AUTOGEN:BEGIN -->

**Feature ID**: 042 · **Status**: `implement` · **Depends on**: 032, 039, 063

A C-ABI executor library, built here from this project's Vulkan, OpenGL and
OpenCL host backends, that the device loads by its executor property: one rvk
context is one session on one worker, commands decode into the backend for the
context's sub-API, host-visible and guest-backed blobs are imported rather
than copied, and every decode or device-loss failure becomes a fault on the
wire. An executor conformance suite in this repository holds any executor
library to the contract.

### Status meaning

Build it, test it to the constitution's standard, and report the capabilities it enables.

### Note

This repository owns all of it: the ABI (src/device/abi/rvk_executor.h), the
conformance suite, the device side, and the backends themselves. The wire it
decodes is generated by feature 063.

### Design rules — binding on this feature

Constitution Principle III and [`CLAUDE.md`](../../CLAUDE.md). Restated here because it is checked at review, not assumed:

- **Every unit of behaviour is a class that owns state.** No static member functions. No stateless class used as a namespace. No free function outside the two ABI boundaries (`DxgkDdi*` entry points in `src/core/ddi/`, and `extern "C"` entry points), each one line with no logic.
- If functions thread the same handle, buffer, bounds or platform through their parameters, **that parameter is a member**. Make it a class and inject its dependencies at construction.
- Name the classes this feature adds before writing them, and say which kind each is: an **object class** (one instance per real thing) or a **system class** (a long-lived service owning a collection).
- Dependencies injected at construction. No global, no singleton, no file-scope state.
- Data members private, trailing underscore. Classes `PascalCase`, methods and locals `snake_case`. No `Manager`, `Helper`, `Utils`, `Handler`, `Impl`, `process()`, `handle()`.
- One class per header, named for it. A header declares; it does not define. One responsibility per class, statable without an "and".
- Errors are `av::Status` values. No exceptions, no RTTI, no C++ standard library, no `new`/`delete` (placement new only in `ObjectStorage`). Cleanup is RAII via `ScopeExit`, never repeated per branch.
- Fallible construction is two-phase: trivial constructor, `initialize(...)` returning `Status`.
- Every public method declares its IRQL ceiling via `platform_.require_irql_at_most(...)`.

Constitution Principle III applies in full. Concretely, this feature is not done until:

## User Scenarios & Testing *(mandatory)*

Users: the QEMU device, which today loads the echo executor the tests build and
therefore runs no host GPU work at all, and the developers of this repository,
who need the generated server dispatch attached to a real host Vulkan, OpenGL
and OpenCL.

**What changed, and why this spec was rewritten.** It was first written while
render-server was a pinned build input: the executor library was to be built
from render-server's server backends, render-server was to export a C ABI and a
pkg-config file, and its own suite was to fuzz its own decoders. Feature 063
settled that this project takes render-server's registry generators and nothing
else. **The executor is this project's, in this repository.** It implements the
ABI feature 032 already defined, it decodes with the generated server dispatch
in `src/proto/generated/*/`, and the backends underneath it are written here
against the host's real APIs. A hostile frame reaching that decoder is this
repository's problem and this repository's fuzz gate.

### User Story 1 - The device runs this project's backends (Priority: P1)

**Independent Test**: the qemu configuration loads the executor library by the
`executor=` property; the virtio-gpu suites create a Vulkan context, submit a
stream that creates an instance and enumerates devices, and read a reply that
names the host GPU the device is bound to.

**Acceptance Scenarios**:

1. **Given** a device realized with the executor library, **When** its capset is
   read, **Then** it offers exactly the sub-APIs (Vulkan, OpenGL, OpenCL) the
   library reports it can execute on the bound host GPU.
2. **Given** an rvk context created for a sub-API, **When** the guest submits a
   command stream on its ring, **Then** the context's worker splits the batch
   into commands and hands each to the executor, which decodes the payload with
   that sub-API's generated server dispatch, runs it on the host API, writes the
   reply the device asked for, and the device advances the fence the submission
   names.
3. **Given** two contexts of different sub-APIs, **When** both submit, **Then**
   each runs on its own worker and neither observes the other's state.

### User Story 2 - Memory is imported, not copied (Priority: P1)

**Independent Test**: the executor conformance suite creates a host-visible blob
and a guest-backed blob through the device, asks the executor to import each, and
checks the executor's view of a byte written by the guest side without a
transfer command.

**Acceptance Scenarios**:

1. **Given** a host-visible blob, **When** a stream uses it as Vulkan device
   memory, a GL buffer or CL memory, **Then** the executor uses the host memory
   the blob already is.
2. **Given** a guest-backed blob on a host where external host-memory import is
   unavailable (feature 039), **When** a stream uses it, **Then** the executor
   copies at the boundary the capset advertises, and says so in its capabilities.
3. **Given** ABI version 1, which has no blob operation at all, **When** this
   feature adds one, **Then** the device refuses a library whose version it does
   not know, and the conformance suite checks both versions it accepts.

### User Story 3 - Any executor is held to the contract (Priority: P1)

**Independent Test**: the executor conformance suite runs against the echo
executor and this project's library alike.

**Acceptance Scenarios**:

1. **Given** an executor library, **When** the suite runs, **Then** it checks ABI
   version negotiation, context create and destroy, command execution, replies,
   replies larger than the capacity offered, blob import and release, faults and
   teardown with contexts still live.
2. **Given** a malformed or truncated command payload, **When** it is submitted,
   **Then** the executor answers undecodable, the device faults that context, and
   every other context keeps running.

### Edge Cases

- A guest-authored stream with a command size past the ring, a nested length
  that overflows, an unknown command id, a handle the context never created, or a
  blob id outside the context: a fault on the wire for that context, no read
  outside the payload, no crash under ASan (constitution V).
- The host driver reports device loss: every context on that GPU faults, the
  device reports it in each fence page, and new contexts are refused until
  reset.
- The guest destroys a context while its worker executes: the executor finishes
  the call it is in - every call must return - releases its imports, and the
  context's memory is not touched afterwards.
- ABI version mismatch between the device and the library: realize fails with a
  named error, and the device offers no capset rather than a partial one.
- A stream blocks on host GPU work longer than the guest's TDR window: the
  executor reports progress through the heartbeat the device exposes to
  `QueryEngineStatus` (feature 033), not ring occupancy.
- A host with no Vulkan, no GL or no CL at all: the library reports the sub-APIs
  it can serve and the capset offers only those, rather than failing realize.

## Requirements *(mandatory)*

- **FR-001**: This repository owns the contract: `rvk_executor.h` (ABI v1 and its
  successors), the device's loading and validation of it, and the executor
  conformance suite. The ABI is C; no C++ type crosses it.
- **FR-002**: This repository also builds the library that implements it - a
  shared object exporting `rvk_executor_ops` over its own Vulkan, OpenGL and
  OpenCL backends, built by this build like every other target. Nothing fetches,
  links or pkg-configs render-server.
- **FR-003**: *Dropped.* It required render-server's backends to accept a
  per-context attachment in place of their shared region. There is no such
  region: the device owns the ring, the reply area and the blob table, and
  `rvk_executor.h` hands the executor one command's payload at a time.
- **FR-004**: One rvk context is one executor on one device worker; the executor
  creates no threads that call back into the device, and every call it is given
  returns so that destroy and reset can wait on it.
- **FR-005**: Every decode failure, host API error that loses the device, and
  unknown command becomes a context fault on the wire; the executor never
  aborts the QEMU process.
- **FR-006**: Blob import prefers zero-copy (host-visible memory as it is; guest
  memory by external host-memory import through a memfd window) and falls back
  to copies only where the capset says so. ABI version 1 carries no blob
  operation, so this is the ABI's next version, and the device accepts both.
- **FR-007**: The executor reports, per bound host GPU, which sub-APIs and which
  memory import paths it supports; the capset reports only those.
- **FR-008**: The generated decoder is fuzzed in this repository, by
  `tests/fuzz/fuzz_generated_decode.cpp` (feature 063). This feature fuzzes the
  layer above it: the ABI boundary and the backends, with hostile command ids,
  payloads and blob tables, and the required outcome is a fault, never a crash.
- **FR-009**: The library decodes with the generated server dispatch in
  `src/proto/generated/{vulkan,opengl,opencl}/`; no hand-written code in this
  feature re-implements the wire or the protocol ids, and a command the profile
  does not select is one the executor answers unknown for.
- **FR-010**: This feature records what the library may be built with, and where
  the line falls. `src/proto` and `src/device` have no C++ standard library, no
  exceptions and no RTTI; a host-side shared object is an ordinary Linux binary
  and may be allowed more. The decision is written down here and in feature
  063's `contracts/generated_code.md`, because it is what settles whether the
  `server_dispatch` emitter may keep its `std::vector` (feature 063, T016).

## Success Criteria *(mandatory)*

- **SC-001**: The conformance suite passes for the echo executor and for this
  project's executor library, under ASan and UBSan.
- **SC-002**: A Vulkan triangle, an OpenGL clear and an OpenCL vector add run
  through the executor and their results are read back from the reply. The
  conformance suite drives them: it builds the frames with the generated
  serializers and hands them to the ABI. The same three driven from a real guest
  through the transport and the ICDs are feature 044, which is what that feature
  is for.
- **SC-003**: A byte-flip sweep of a valid stream produces faults, never a
  crash, for 60 seconds of fuzzing per sub-API - one fuzz target per sub-API,
  since the gate's budget is per target.

## Assumptions

- The generated server dispatch covers enough of each API for the workloads
  SC-002 names; widening that is a change to feature 063's profiles, reviewed as
  a wire change.
- Host OpenGL is surfaceless EGL, and host OpenCL is the host's ICD loader.
- The host's Vulkan, OpenGL and OpenCL are found at runtime by the loader, so the
  library can be built on a machine that has the headers without having a GPU.

## Out of Scope

- The guest transport and drivers (043, 045, 050, 052).
- Changing the wire. The commands, their serialization and their protocol ids
  are the generator's output (feature 063); a change to any of them is a change
  there, and this feature consumes what it is given.
- Any use of render-server: no source, no library, no pkg-config file, no patch
  sent upstream.

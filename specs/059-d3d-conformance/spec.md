**Feature ID**: 059 · **Status**: `implement` · **Depends on**: 057, 058, 064

The HLK graphics tests as a correctness oracle (unsigned), DXVK and
vkd3d-proton test suites, and games and benchmarks through both the Microsoft
runtime and the translation layers, run in the guest with frames compared
against references and every reported feature level backed by a passing test.

### Status meaning

Build it, test it to the constitution's standard, and report the capabilities it enables.

### Design rules — binding on this feature

Constitution Principle III and [`CLAUDE.md`](../../CLAUDE.md). Restated here because it is checked at review, not assumed:

- **Every unit of behaviour is a class that owns state.** No static member functions. No stateless class used as a namespace. No free function outside the two ABI boundaries (`DxgkDdi*` entry points in `src/core/ddi/`, and `extern "C"` entry points), each one line with no logic.
- If functions thread the same handle, buffer, bounds or platform through their parameters, **that parameter is a member**. Make it a class and inject its dependencies at construction.
- Name the classes this feature adds before writing them, and say which kind each is: an **object class** (one instance per real thing) or a **system class** (a long-lived service owning a collection).
- Dependencies injected at construction. No global, no singleton, no file-scope state.
- Data members private, trailing underscore. Classes `PascalCase`, methods and locals `snake_case`. No `Manager`, `Helper`, `Utils`, `Handler`, `Impl`, `process()`, `handle()`.
- One class per header, named for it. A header declares; it does not define. One responsibility per class, statable without an "and".
- Errors are `av::Status` values. No exceptions, no RTTI, no C++ standard library, no `new`/`delete` (placement new only in `ObjectStorage`). Cleanup is RAII via `ScopeExit`, never repeated per branch.
- Fallible construction is two-phase: trivial constructor, `initialize(...)` returning `Status`.
- Every public method declares its IRQL ceiling via `platform_.require_irql_at_most(...)`.

### Test requirements

Constitution Principle III applies in full. Concretely, this feature is not done until:

- every branch of every function it adds to `src/core`, `src/device` or `src/proto` is covered, or marked `AV_UNTESTABLE` with a justification;
- each stateful module it adds exports an invariant function that tests call after **every** mutation;
- every function it adds that reads bytes from outside its own address space has a hostile-input table test and a libFuzzer target with a committed corpus;
- the allocation-failure sweep passes: with each allocation site failed in turn, no crash and no leak;
- IRQL annotations are present and the mock's IRQL checker is satisfied;
- `tools/check_symbol_tests.py` reports no untested exported symbol.

## User Scenarios & Testing *(mandatory)*

<!-- Written by /speckit-specify or by hand. The autogen block above is regenerated by tools/gen_specs.py; everything below is preserved. -->

Users: the driver's developers and anyone deciding whether to trust rvkgpu with
a Direct3D workload. They need a repeatable, automated answer to "does D3D
work, and did it get worse" - through both routes D3D takes on this adapter:
the Microsoft runtime over `rvkumd.dll` (features 056, 057) and the
translation layers DXVK and vkd3d-proton over the Vulkan ICD (feature 047).

### User Story 1 - The HLK graphics tests as a correctness oracle (Priority: P1)

**Independent Test**: the in-guest runner installs the HLK client test
binaries needed for the selected D3D11 and D3D12 graphics tests, runs them
against the rvkgpu adapter without a controller or signing, and parses their
logs into a pass/fail table in the work directory.

**Acceptance Scenarios**:

1. **Given** a guest with the driver package, **When** the selected HLK
   graphics tests run, **Then** each result is recorded with its test name,
   and the run's pass count is compared against a committed ratchet.
2. **Given** a test that fails, **Then** the frame or log that failed is kept
   with the run's diagnostics, and a regression below the ratchet fails the
   gate.
3. **Given** a reported feature level, **Then** every HLK test that the level
   requires is in the selection; a level with a failing required test is not
   reported.

### User Story 2 - DXVK and vkd3d-proton test suites (Priority: P1)

**Independent Test**: the translation layers' own test programs and a D3D9,
D3D11 and D3D12 sample set run in the guest with the layers placed beside
them; results are parsed and ratcheted like the HLK run.

**Acceptance Scenarios**:

1. **Given** vkd3d-proton's test suite, **When** it runs on rvkgpu, **Then** its
   pass count is at least the committed ratchet.
2. **Given** the same D3D12 sample through the system runtime and through
   vkd3d-proton, **Then** both frames match the reference within tolerance.

### User Story 3 - Games and benchmarks (Priority: P2)

**Independent Test**: a list of freely redistributable D3D9/11/12 benchmarks
and demos run scripted for a fixed duration; frames at fixed timestamps are
captured on the host from the scanout and compared against references, and
frame times are recorded for feature 062.

**Acceptance Scenarios**:

1. **Given** a benchmark, **When** it completes, **Then** it exits cleanly, no
   TDR or device removal occurred, and captured frames match.
2. **Given** a crash or hang, **Then** the runner collects the dumps and the
   verdict names the application and step.

### Edge Cases

- A test needs a capability the host GPU lacks: it is recorded as not
  applicable with the capset bit that excludes it, not as a pass.
- A test triggers TDR: the runner records it, the guest recovers, and later
  tests still run.
- 32-bit test binaries under WoW64.
- Non-deterministic rendering (timing-based effects): compared at fixed
  frames with a per-test tolerance recorded beside its reference.
- References made on one host GPU used on another: references are keyed by
  GPU class, and a missing reference is reported, not treated as a pass.

## Requirements *(mandatory)*

- **FR-001**: The in-guest runner gains an application-suite stage that pushes
  test binaries, runs each with a timeout, and collects logs, frames and dumps.
- **FR-002**: Results are parsed into a committed ratchet per suite and host
  GPU class; the gate fails on a regression, and raising the ratchet is a
  reviewed change.
- **FR-003**: Every reported Direct3D feature level and option maps to the
  tests that justify it; a mapping with a failing test withdraws the claim
  (constitution VI).
- **FR-004**: Frame comparison uses host-side capture of the scanout, so the
  guest's readback path is not what is being tested.
- **FR-005**: Test binaries and references are fetched by pinned hash, not
  committed if their licence forbids it; nothing outside the repository is
  referenced by path.
- **FR-006**: The HLK tests run unsigned as an oracle; nothing here pursues
  WHQL certification.

## Success Criteria *(mandatory)*

- **SC-001**: One command runs the D3D suites in the guest and yields a verdict
  and per-suite pass counts.
- **SC-002**: Every reported feature level has a passing required-test set.
- **SC-003**: The benchmark list completes without TDR on each supported host
  GPU class.

## Assumptions

- Features 057 and 058 are complete; the HLK client binaries can be obtained
  and run in a test-signed guest.
- Automated runs use a GL-capable headless QEMU display for host-side capture.

## Out of Scope

- WHQL submission, HLK controller infrastructure and production signing.
- Performance thresholds: feature 062 records and gates them.
- Video and DirectML test content.

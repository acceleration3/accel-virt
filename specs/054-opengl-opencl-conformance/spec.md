# Feature Specification: OpenGL and OpenCL: conformance in the guest

**Feature Branch**: `054-opengl-opencl-conformance`

**Created**: 2026-09-11

**Status**: Draft

<!-- AUTOGEN:BEGIN -->

**Feature ID**: 054 · **Status**: `implement` · **Depends on**: 051, 052, 053

Khronos OpenGL conformance and piglit subsets and an OpenCL CTS subset, run in
the guest by the in-guest runner with rendered output compared against
references, pass rates recorded as a ratchet, and every claimed version and
extension backed by a passing test.

### Status meaning

Build it, test it to the constitution's standard, and report the capabilities it enables.

### Design rules — binding on this feature

Constitution Principle III and [`CLAUDE.md`](../../CLAUDE.md). Restated here because it is checked at review, not assumed:

- **Every unit of behaviour is a class that owns state.** No static member functions. No stateless class used as a namespace. No free function outside the two ABI boundaries (`DxgkDdi*` entry points in `src/core/ddi/`, and `extern "C"` entry points), each one line with no logic.
- If functions thread the same handle, buffer, bounds or platform through their parameters, **that parameter is a member**. Make it a class and inject its dependencies at construction.
- Name the classes this feature adds before writing them, and say which kind each is: an **object class** (one instance per real thing) or a **system class** (a long-lived service owning a collection).
- Dependencies injected at construction. No global, no singleton, no file-scope state.
- Data members private, trailing underscore. Classes `PascalCase`, methods and locals `snake_case`. No `Manager`, `Helper`, `Utils`, `Handler`, `Impl`, `process()`, `handle()`.
- One class per header, named for it. A header declares; it does not define. One responsibility per class, statable without an "and".
- Errors are `av::Status` values. No exceptions, no RTTI, no C++ standard library, no `new`/`delete` (placement new only in `ObjectStorage`). Cleanup is RAII via `ScopeExit`, never repeated per branch.
- Fallible construction is two-phase: trivial constructor, `initialize(...)` returning `Status`.
- Every public method declares its IRQL ceiling via `platform_.require_irql_at_most(...)`.

### Test requirements

Constitution Principle III applies in full. Concretely, this feature is not done until:

- every branch of every function it adds to `src/core`, `src/device` or `src/proto` is covered, or marked `AV_UNTESTABLE` with a justification;
- each stateful module it adds exports an invariant function that tests call after **every** mutation;
- every function it adds that reads bytes from outside its own address space has a hostile-input table test and a libFuzzer target with a committed corpus;
- the allocation-failure sweep passes: with each allocation site failed in turn, no crash and no leak;
- IRQL annotations are present and the mock's IRQL checker is satisfied;
- `tools/check_symbol_tests.py` reports no untested exported symbol.

## User Scenarios & Testing *(mandatory)*

<!-- Written by /speckit-specify or by hand. The autogen block above is regenerated by tools/gen_specs.py; everything below is preserved. -->

Users: the driver's developers, and anyone deciding whether to trust the
versions and extensions the OpenGL and OpenCL drivers report. Constitution VI
says a capability is never reported before it is implemented and tested; for
public APIs "tested" means the Khronos conformance tests, not only the
project's own programs.

Starting point: render-server has its own OpenGL tests (t00-t55, pixel-compared
render tests, interop tests) and OpenCL tests (t01-t33), but no Khronos OpenGL
CTS, no piglit and no OpenCL CTS. kb 11 M7 is done when each API's existing
test suite passes in the guest.

### User Story 1 - Conformance suites run in the guest from Linux (Priority: P1)

**Independent Test**: the in-guest runner's tests (tests/tools, fake QEMU)
cover pushing a suite, running a named subset with a timeout per test, pulling
its results, and parsing them into pass, fail, crash and timeout.

**Acceptance Scenarios**:

1. **Given** a prepared image and a build, **When** the runner is asked for the
   OpenGL suite, **Then** it pushes the Khronos OpenGL CTS (GL 4.6 and
   compatibility mustpass lists) and a piglit subset, runs them on the rvkgpu
   adapter, and brings back per-test results and logs.
2. **Given** the OpenCL suite, **Then** it runs the OpenCL CTS subset for the
   version and extensions the ICD reports.
3. **Given** render-server's own GL and CL tests, **Then** they run in the same
   guest session and report in the same format.
4. **Given** a test that hangs or crashes the application, **Then** it is
   recorded as such, the next test runs, and a TDR or bugcheck is collected by
   the runner's diagnostics.

### User Story 2 - Pass rates are a ratchet (Priority: P1)

**Independent Test**: a results comparator is tested against recorded result
sets: a new failure, a lost pass, a removed test and a reported extension with
no passing test each fail the check.

**Acceptance Scenarios**:

1. **Given** a committed expectations file per suite and host GPU class,
   **When** a run passes a test previously failing, **Then** the expectation is
   tightened in the same change.
2. **Given** a run that fails a test previously passing, **Then** the gate
   fails and names it.
3. **Given** the ICDs' reported versions and extension strings, **When** any
   reported item has no passing conformance test, **Then** the gate fails.

### User Story 3 - Rendered output is compared, not just exit codes (Priority: P2)

**Independent Test**: image comparison is tested with identical, off-by-one,
sub-threshold and grossly different images.

**Acceptance Scenarios**:

1. **Given** render tests, **When** frames are captured in the guest, **Then**
   they are compared against references recorded on the same host GPU class
   natively, within a stated tolerance.

### Edge Cases

- A host GPU without an extension: the test is expected to be absent, not
  failing, because the extension is not reported.
- Different host GPU drivers producing slightly different rasterization: one
  expectations file per GPU class.
- Suites that exceed the guest's step timeout: split into shards.
- 32-bit ICDs: the OpenGL and OpenCL suites run in 32-bit form as well.
- A test that leaves the device lost: the runner restarts the guest before the
  next shard.

## Requirements *(mandatory)*

- **FR-001**: Suites run through `tools/guest/run_guest_suite.py`, reusing its
  preparation, collection and crash handling.
- **FR-002**: Suites are fetched pinned by version and hash, like the Windows
  kit; nothing outside the repository is referenced by path.
- **FR-003**: Expectations are committed per suite and host GPU class; the
  gate compares, it does not merely report.
- **FR-004**: Every version and extension the OpenGL and OpenCL drivers report
  maps to at least one passing test in the committed expectations.

## Success Criteria *(mandatory)*

- **SC-001**: render-server's GL and CL tests all pass in the guest (kb 11 M7).
- **SC-002**: OpenGL CTS and OpenCL CTS subsets run to completion in the guest
  with recorded pass rates for each host GPU class available.
- **SC-003**: No reported extension lacks a passing test.

## Assumptions

- Features 050-053 are complete.
- Khronos conformance suites build for Windows x64 and x86 with the project's
  toolchain or are fetched prebuilt and pinned.

## Out of Scope

- Official Khronos conformance submission.
- Vulkan conformance (feature 048) and Direct3D (feature 059).

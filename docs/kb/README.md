# WDDM 3.2 Knowledge Base

Target: build a **paravirtualized WDDM 3.2 display miniport driver** for a
Windows guest on QEMU/KVM. The guest driver speaks virtio-gpu to a custom
in-process QEMU device, `virtio-gpu-rvk-pci`, which executes Vulkan/GL/CL on
the host GPU. `render-server` supplies only the generated command
serialization. No ivshmem, no separate host process.

Everything here is derived from two sources, both obtained on this Linux box
with no Windows install:

1. **Microsoft's own WDK 26100 / SDK 26100 headers**
   (`third_party/windows-kit/include/`, fetched by `tools/fetch_windows_kit.sh`) — the
   normative DDI contract. `DXGKDDI_INTERFACE_VERSION_WDDM3_2 == 0x11007`, and
   the SDK 26100 headers default to exactly that.
2. **Reverse engineering of shipping Microsoft binaries** (`re/bin/`, pinned in
   `tools/re/binaries.txt` and fetched by `tools/re/build_workspace.sh`), all
   with public PDBs pulled from `msdl.microsoft.com`.

## The binaries and why each one is here

| Binary | Publics | Why it matters |
|---|--:|---|
| `dxgkrnl.sys` | 16714 | The *caller* side of the DDI. Also contains the entire GPU-PV paravirtualization stack (`DXGVIRTUALGPUMANAGER_PARAV`, `DXGVAILOBJECT`, 92 `DXGKVMB_COMMAND_*` messages). |
| `dxgmms2.sys` | 4065 | VidMm (video memory manager) + VidSch (scheduler). Paging, residency, GPU VA, preemption. |
| `basicrender.sys` | 289 | **The WARP KMD.** A complete, WDDM 3.2, render-capable miniport with *no hardware behind it*. The single closest existing thing to what we are building. |
| `basicdisplay.sys` | 318 | The display-only (KMDOD) miniport. VidPn/scanout reference. |
| `vkrnlintvsp.sys` | 292 | Cross-VM events, mutexes and shared state registers — the host↔guest sync plumbing GPU-PV rides on. |
| `vpci.sys` | — | Guest-side virtual PCI, for how a synthetic GPU gets enumerated. |
| `d3d12core.dll`, `d3d12.dll`, `dxgi.dll`, `dxcore.dll` | — | User-mode side: runtime, adapter enumeration, swapchain. |

**Important limitation, stated up front:** these PDBs report
`Is stripped: true`. They carry public symbols — names and addresses — and
**no type information**. Struct layouts in this KB come from the WDK headers
(normative) or from decompilation (inferred, and marked as such). Nothing here
claims a layout it did not get from one of those two places.
